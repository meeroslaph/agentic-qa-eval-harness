# CLAUDE.md

Project context for Claude Code.

## What this repo is

A small TypeScript proof-of-concept showing **how to build a QA / evaluation
harness around an agentic workflow**. Toy invoice-approval domain; the
harness is the focus. See [README.md](README.md) and [AGENTS.md](AGENTS.md).

## Important commands

```bash
npm install
npm test           # vitest, all green
npm run typecheck  # strict TS
npm run build      # tsc emit to dist/
npm run eval       # deterministic baseline report
npm run eval:flaky # flaky-mode report (intentionally surfaces inconsistencies)
```

## Architecture summary

- **`src/domain`** — `Invoice` type and the canonical business rules. Single
  source of truth for decision logic.
- **`src/workflow`** — `ModelClient` interface + two mocks
  (`DeterministicMockModelClient`, `FlakyMockModelClient`), `runWorkflow.ts`
  orchestrator, and a structured `TraceRecorder`.
- **`src/eval`** — golden cases, evaluators (outcome, trajectory,
  consistency, cost/latency, escalation), `runEvalSuite`, markdown report
  generator.
- **`src/agent-instructions`** — versioned markdown capability modules
  (intake, routing, review).
- **`tests`** — vitest tests covering rules, workflow, evaluators, model
  client abstraction, and golden case coverage.
- **`reports`** — committed sample reports, regenerated by `npm run eval*`.

## Hard constraints — DO NOT change without explicit request

- **The model layer must remain mocked / provider-agnostic.** No live calls
  to OpenAI, Anthropic, Ollama, or any hosted LLM. The `ModelClient`
  abstraction is the seam where a real adapter could be added later.
- **No LangChain, no LangGraph.** First-principles only.
- **No SaaS tracing, no external observability backend, no database, no
  server, no UI.**
- **No Claude Skills, no proprietary agent runtime.**
- **No new heavyweight dependencies.** `zod`, `vitest`, `tsx`, `typescript`
  are the baseline; justify any addition.

## Style

- Strict TypeScript. Avoid `any`.
- Short functions. Comments only where the *why* is non-obvious.
- Match existing patterns — explicit domain types, no premature abstraction.

## When generating reports

`reports/baseline-report.md` and `reports/flaky-report.md` are committed as
example artefacts. They should be deterministic per (seed, runs-per-case)
and safe to commit. The flaky report intentionally shows inconsistencies —
that is the demo.
